Authoring surface & config

The tiny, non-secret app-level configuration that opts an agent app into the ACA Sandbox backend — and the startup checks that refuse unsafe combinations.

No new parent decision number App-level opt-in v1 · fail-closed Finalized

1The big idea

This sub-FRD is the part an app author sees: one app-level session_runtime block selects the aca_sandbox backend and points the runtime at the Sandbox Group. Markdown-first agent authoring stays the same.

In plain terms: authors do not describe sandbox internals. They opt the app into ACA Sandbox, provide one non-secret resource identifier, and may set one app-level retention override. Secrets, state storage, egress enforcement, image pinning, and residency stay in deployment/IaC.

◆Small surface

provider: aca_sandbox is explicit opt-in; absence of the block keeps today's in_process behavior.

◆App-level only

v1 does not allow per-agent sandbox-group, harness, or retention selection. Revisit only if one deployed app needs materially different trust, egress, SKU, or retention profiles.

◆Non-secret by design

The authored identifier is safe to keep with source. Operational trust resources remain provisioned settings, not .agent.md front matter.

2The authored shape

The source document gives concrete v1 key names. The ACA SDK spike may still refine the accepted value format for the resource ID, but not the authored key names.

session_runtime: provider: aca_sandbox # in_process (default) | aca_sandbox harness: maf # only supported v1 value aca_sandbox: sandbox_group_resource_id: $ACA_SANDBOX_GROUP_RESOURCE_ID retention: # optional app-level override auto_suspend_idle: 5m reclaim_idle: 24h

◆What belongs here

provider, harness, nested aca_sandbox.sandbox_group_resource_id, and optional retention. The group region is derived from the resolved ARM resource, not authored.

◆What does not

No run-duration, egress, credential, packaging, disk, content, storage, or identity fields. Run duration reuses the existing agent timeout; egress is derived from existing capability config.

3Boundaries that matter

The authoring block is intentionally not a back door into lower runtime planes.

Custom sandbox image is IaC-plane, not authoring

The runtime-provided generic harness image is pinned by digest in customer IaC, alongside the Sandbox Group and residency choices (0008.4). If v1 uses a custom disk image escape hatch, it is still provisioned there — never as an app authoring field.

Any custom image must be MAF-conformant

v1 is MAF-only. A custom image must pass the golden-trace conformance gate owned by 0008.7; a non-MAF bring-your-own harness is deferred to a separate FRD.

Retention override is author-owned but constrained

The optional retention block is app-scoped. If omitted, Sandbox Group lifecycle defaults apply. If set, the values are validated at startup and applied per sandbox at create; lifecycle defaults and semantics are owned by 0008.12.

4Startup validation fail-closes

The backend does not silently fall back when the surface and deployment plane disagree. Unsupported combinations stop startup with specific diagnostics.
